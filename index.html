1. Problem & approach

Why sorting matters in smart irrigation.

📍 Problem

Sensors report soil-moisture (%) for every field. Water is limited, so the farmer must know which fields are driest without scanning the whole list each time.

⚡ Why Quick Sort

It sorts in place with O(n log n) average time. It splits the fields around a pivot: drier ones go left, wetter ones right, then each side is solved the same way (divide & conquer).

🔁 Pipeline

Each step of this model is one stage of the real system:
Sensors→Quick Sort→Priority list→Greedy water allocation→Sprinklers

5. Viva Q&A

 
Why is Quick Sort a divide-and-conquer algorithm?
Divide: partition around a pivot. Conquer: recursively sort both sides. Combine: nothing to do, because sorting is in place.

 
What is the worst case and how do we avoid it?
Already-sorted input with the last element as pivot gives n(n−1)/2 comparisons. A random or median-of-three pivot makes it very unlikely (our C++ program uses a random pivot).

 
Is Quick Sort stable? Does it matter here?
No. Equal-moisture fields may swap order, so the code breaks ties by field ID to keep results deterministic.

 
Why a greedy allocation after sorting?
Giving water to the most urgent field first is the best local choice when the goal is to cover the driest fields; sorting makes that choice an O(n) scan.

6. Conclusion & future scope

 
✅ Result
Quick Sort ranks fields by dryness in O(n log n) average time, and the ranking drives fair, urgent-first water use.

 
🌍 Real-world use
Drip and sprinkler scheduling, canal water distribution, greenhouse zones, any “most urgent first” resource problem.

 
🚀 Future scope
Live IoT sensors (ESP32), weather forecasts, crop-specific priority weights, and a priority queue (heap) for continuously arriving readings.
